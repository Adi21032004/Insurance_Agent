# Tech stack

- `backend/`: FastAPI with SQLAlchemy Core tables held in one `MetaData`. Claims, decisions, payments, sign-offs, runs, run claims, model calls and work times are persisted in SQLite locally or Postgres, including Supabase, when `DATABASE_URL` is set. The backend calculates payouts and guards sign-off and payment operations. Claim operations live in `main.py`; dispatch and evaluation operations live in `runs.py`.
- `agent/`: a LangGraph `StateGraph` for each claim and a dispatcher graph that fans out work with `Send`, retries transient failures with `RetryPolicy` and limits parallel claim agents with `max_concurrency`. The dispatcher has no model. `work_claim(claim_id, graph)` starts a claim, `carry_on(claim_id, graph)` resumes a saved thread, and `work_in_run(claim_id, run_id, new_graph)` starts or resumes one claim in a dispatch. `PostgresSaver` stores checkpoints in the `undercover` schema through a shared pool of four connections, with a separate saver per claim graph. Without `DATABASE_URL`, the local service uses an in-memory saver. GPT-6 Luna with low reasoning effort is the default; `MODEL_NAME` can override it. The agent records token counts, cost from `usage.cost` and claim work time. Langfuse traces claim work when its keys are configured and tags run work with its run id.
- `agent/service.py`: the agent's HTTP service. The backend calls it through `backend/agent_service.py`, at `UNDERCOVER_AGENT` or `http://127.0.0.1:8002`. It starts claims, dispatches and evaluations, and resumes claims after sign-off.
- `agent/dispatcher.py`: selects waiting and in-progress claims, fans out one worker per claim, applies retry policy and finishes dispatch or evaluation work.
- `dashboard/`: React, Vite and TypeScript. It displays the queue, dispatches, claim progress, decisions, handler sign-offs and payments. The Scoreboard starts and displays evaluations against copies of labelled claims.
- `e2e/`: Playwright tests with a deterministic agent stand-in and an isolated temporary SQLite database.
- `data/`: approved business and evaluation data. Only the backend's seed code reads `data/evals/`; claim agents never see the answer key.

Python 3.12 with uv, all in the root `pyproject.toml`. Node 26. `npm run dev` starts the backend, agent service and dashboard; `npm run seed` rebuilds the application tables in the configured database. Seeding removes the current application records before rebuilding them. Set `DATABASE_URL` to the Supabase Postgres URI when using Supabase and set `OPENROUTER_API_KEY` for live model calls. `MODEL_NAME` can select another model, including `openrouter/free`. Langfuse tracing uses `LANGFUSE_PUBLIC_KEY` and `LANGFUSE_SECRET_KEY`. `UNDERCOVER_CLAIM_TIMEOUT_SECONDS` sets claim-call timeouts (120 seconds by default).
