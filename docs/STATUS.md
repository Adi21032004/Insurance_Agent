# Status

The pilot is complete. All five phases are complete.

The harness implementation is in progress. Phases 1 through 4 of 6 are complete. SQLite persists capped runs, atomically reserved claims, ordered to-do items, attempt counts, per-claim failures and run summaries. Only one run can be active. Leases let startup and new-run requests detect and resume expired work. A first failure retries with a fresh claim agent and thread; a second failure routes the claim to handler review. If a decision is already saved, a retry resumes only the pending payment step. Repeated decision, sign-off and payment writes are idempotent with unique database records. Pilot databases migrate duplicate decision and payment rows by retaining the earliest and recording the removal in claim activity. The backend searches and reads individual policy wording and claims manual sections, records each section read on the claim, converts manual amounts to INR, and returns separate queue and claim instructions. The queue agent plans and reserves a batch, then creates a fresh claim agent and thread for each selected claim. The agent claim context does not include either full source document.

- `backend/`: SQLite seeds the 25 queue claims from approved business data files; read APIs return the queue and full claim context in INR. The company setting `usd_to_inr_rate` drives amount conversion and the sign-off threshold. The API records progress and policy decisions, calculates payouts from selected source items, enforces handler sign-off, and records simulated payments.
- `agent/`: `run_queue(run_id, thread_id)` plans a capped batch and delegates each claim to a fresh `run(claim_id, thread_id)` LangChain agent. It retries one failed attempt, continues after a claim needs handler review, and resumes a saved approval from persisted state. Claim calls use `UNDERCOVER_CLAIM_TIMEOUT_SECONDS` (120 seconds by default); run leases use `UNDERCOVER_RUN_LEASE_SECONDS` (300 seconds by default). The claim agent reads claim data, policy and manual sections, and its instructions through backend APIs, records progress and decisions, requests backend payout calculations, and uses the guarded simulated payment operation. The default OpenRouter model is `deepseek/deepseek-v4.1-flash` with low reasoning effort; `MODEL_NAME` overrides it.
- `dashboard/`: the handler workspace shows the 25-claim queue, claim evidence and policy context, INR amounts, agent decision and progress, read-only instructions, handler sign-off and simulated payment controls.
- `e2e/`: two Playwright flows verify standard approval and payment plus over-limit sign-off and payment with a deterministic stub model and isolated temporary database.

The seed records retain their original USD values in SQLite. The fixed pilot rate of ₹83.00 per USD is stored in `data/company.json`; payouts over ₹83,000 require handler sign-off. Payments are local simulations. No evaluation or security claim data is loaded.

Install with `uv sync` and `npm install`, then run the app with `npm run dev`. The complete check passed with 35 Python tests at 92.88% coverage, 8 dashboard tests at 86.66% coverage, and 2 Playwright tests. This machine used its installed Chrome via `$env:UNDERCOVER_PLAYWRIGHT_CHANNEL = 'chrome'`; the default Playwright Chromium download timed out.
