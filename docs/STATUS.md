# Status

The pilot is complete. All five phases are complete.

The harness implementation is complete. Automated checks pass; the separate live-model acceptance check is pending because no OpenRouter key is configured. SQLite persists capped runs, atomically reserved claims, ordered to-do items, attempt counts, per-claim failures and run summaries. Only one run can be active. Leases let startup and new-run requests detect and resume expired work. A first failure retries with a fresh claim agent and thread; a second failure routes the claim to handler review. Before closing, the queue agent reconciles every selected task against persisted claim state and retries unfinished work. A saved decision is never duplicated; an approval that needs handler sign-off stays unpaid until sign-off, while an eligible approval with an unsaved payment resumes at payment. Repeated decision, sign-off and payment writes are idempotent with unique database records. Pilot databases migrate duplicate decision and payment rows by retaining the earliest and recording the removal in claim activity. The backend searches and reads individual policy wording and claims manual sections, records each section read on the claim, converts manual amounts to INR, and returns separate queue and claim instructions. The queue agent plans and reserves a batch, then creates a fresh claim agent and thread for each selected claim. The agent claim context does not include either full source document.

- `backend/`: SQLite seeds the 25 queue claims from approved business data files; read APIs return the queue and full claim context in INR. The company setting `usd_to_inr_rate` drives amount conversion and the sign-off threshold. The API persists runs and ordered tasks, tracks claim failures, calculates payouts from selected source items, enforces handler sign-off, and records simulated payments.
- `agent/`: `run_queue(run_id, thread_id)` plans a capped batch and delegates each claim to a fresh `run(claim_id, thread_id)` LangChain agent. It retries one failed attempt, reconciles unfinished selected work, continues after a claim needs handler review, and resumes a saved approval from persisted state. Claim calls use `UNDERCOVER_CLAIM_TIMEOUT_SECONDS` (120 seconds by default); run leases use `UNDERCOVER_RUN_LEASE_SECONDS` (300 seconds by default). The claim agent reads claim data, policy and manual sections, and its instructions through backend APIs, records progress and decisions, requests backend payout calculations, and uses the guarded simulated payment operation. The default OpenRouter model is `deepseek/deepseek-v4.1-flash` with low reasoning effort; `MODEL_NAME` overrides it.
- `dashboard/`: the handler workspace shows the 25-claim queue, a configurable queue-run cap, persisted run to-dos and summary, claim evidence and policy context, recorded source reads, INR amounts, agent decision and progress, read-only queue and claim instructions, handler sign-off and simulated payment controls.
- `e2e/`: three Playwright flows verify standard approval and payment, over-limit sign-off and payment, and a capped queue run with a retry, handler routing, missed-task reconciliation and section reads. They use deterministic stub models and an isolated temporary database.

The seed records retain their original USD values in SQLite. The fixed pilot rate of ₹83.00 per USD is stored in `data/company.json`; payouts over ₹83,000 require handler sign-off. Payments are local simulations. No evaluation or security claim data is loaded.

Install with `uv sync` and `npm install`, then run the app with `npm run dev`. `npm run check` passed with 70 Python tests at 88.33% backend and agent coverage, 12 dashboard tests at 88.49% statement coverage, and 3 Playwright tests. Playwright used installed Chrome through `$env:UNDERCOVER_PLAYWRIGHT_CHANNEL = 'chrome'`; the managed Chromium download timed out. The separate live-model acceptance check remains pending because `OPENROUTER_API_KEY` is not configured on this machine.
